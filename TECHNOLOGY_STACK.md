# Стек технологий Emissium

Emissium — сайт продукта с главной страницей, регистрацией, авторизацией, личным кабинетом и отдельной панелью администратора для управления пользователями и подписками. Клиент работает как React SPA, сервер предоставляет HTTP API с JSON, данные хранятся в SQLite.

## Технологии

Версии npm-пакетов указаны по `package-lock.json` и `server/package-lock.json`. В `package.json` заданы диапазоны допустимых версий; установка через `npm ci` использует версии из lock-файлов.

| Часть проекта | Технология | Версия | Назначение |
| --- | --- | --- | --- |
| Язык | JavaScript, JSX | — | Клиентский и серверный код; ES modules на клиенте, CommonJS на сервере |
| Окружение | Node.js + npm | Рекомендуется Node.js 24.x; также подходит 22.x | Сервер, установка пакетов и сборка клиента |
| Клиент | React (`react`) | 18.3.1 | Компоненты интерфейса и React Hooks |
| Клиент | React DOM (`react-dom`) | 18.3.1 | Отрисовка приложения в браузере |
| Клиент | React Router DOM (`react-router-dom`) | 7.18.1 | Маршруты `/`, `/login`, `/register`, `/profile` через BrowserRouter |
| Клиент | React Context API | В составе React | Состояние авторизации через AuthProvider |
| Клиент | React Icons (`react-icons`) | 4.12.0 | Иконки социальных сетей |
| Интерфейс | HTML5, CSS3 | — | Flexbox, Grid, медиазапросы, CSS-переменные и анимации |
| Интерфейс | Canvas 2D, requestAnimationFrame | API браузера | Анимированный фон |
| Интерфейс | Google Fonts | — | Шрифты Inter и Orbitron |
| Сборка | Vite (`vite`) | 5.4.21 | Сервер разработки, сборка в `dist/`, предварительный просмотр |
| Сборка | @vitejs/plugin-react | 4.7.0 | Поддержка React и JSX в Vite |
| Сервер | Express (`express`) | 4.22.2 | Маршруты API и раздача статических файлов админки |
| Сервер | cors | 2.8.6 | Доступ к API с разрешённых адресов клиента и админки |
| База данных | SQLite через better-sqlite3 | Драйвер 12.11.1 | Локальная БД, SQL-запросы, режим WAL |
| Авторизация | jsonwebtoken | 9.0.3 | Создание и проверка JWT |
| Пароли | bcrypt | 5.1.1 | Хеширование паролей, 12 раундов |
| Разработка сервера | nodemon | 3.1.14 | Перезапуск API при изменении файлов |
| Админка | HTML, CSS, JavaScript | — | Отдельная страница без React; запросы через Fetch API |
| Контейнеризация | Docker, Docker Compose | — | Многоэтапная сборка, запуск от пользователя node, постоянный volume SQLite |

Клиент отправляет запросы через встроенный Fetch API. JWT передаётся в заголовке `Authorization: Bearer …`; при выборе «Запомнить меня» хранится в `localStorage`, иначе — в `sessionStorage`. Срок действия токена составляет соответственно 30 дней или 24 часа. Административные запросы используют заголовок `x-admin-key`.

## Структура

- `src/components/` — интерфейс главной страницы, формы входа и регистрации, карточка профиля и модальное окно смены пароля.
- `src/pages/` — страницы входа, регистрации и профиля.
- `src/context/AuthContext.jsx` — загрузка текущего пользователя и состояние авторизации.
- `src/api/auth.js` — HTTP-запросы к API и хранение JWT.
- `server/index.js` — основной API, включая `/api/health`, `/api/auth` и `/admin`.
- `server/routes/auth.js` — регистрация, вход, получение профиля, изменение email и пароля.
- `server/routes/admin.js` — просмотр пользователей, выдача, продление и сброс подписок.
- `server/db.js` — открытие БД по `DB_PATH` (по умолчанию `server/emissium.db`), создание таблицы `users` и добавление колонок подписки в существующую БД.
- `server/admin.js` и `server/admin-panel/index.html` — отдельный сервер и интерфейс админки.
- `package.json` и `server/package.json` — два независимых набора npm-зависимостей и команд.

## Установка и запуск

Из корня проекта установить оба набора зависимостей:

```powershell
npm ci
npm --prefix server ci
```

Запустить три процесса в отдельных терминалах, каждый раз из корня проекта:

| Процесс | Команда | Адрес по умолчанию |
| --- | --- | --- |
| Клиент | `npm run dev` | http://localhost:5173 |
| API | `npm --prefix server start` | http://localhost:3001 |
| Админка | `node server/admin.js` | http://localhost:3002 |

Для API с автоматическим перезапуском вместо `start` используется `npm --prefix server run dev`.

Сборка и просмотр собранного клиента:

```powershell
npm run build
npm run preview
```

`npm run preview` запускает только просмотр клиента; API запускается отдельно. Vite проксирует запросы `/api` на локальный API через настройку `server.proxy`, которую Vite 5 также использует для preview.

Для запуска всего сайта в Docker доступны `Dockerfile`, `.dockerignore` и `docker-compose.yml`. Команды и описание сборки находятся в [DOCKER.md](DOCKER.md).

## Настройки окружения

| Переменная | Где используется | Назначение / значение по умолчанию |
| --- | --- | --- |
| `PORT` | `server/index.js` | Порт API, по умолчанию `3001` |
| `ADMIN_PORT` | `server/admin.js` | Порт админки, по умолчанию `3002` |
| `JWT_SECRET` | `server/routes/auth.js` | Ключ подписи и проверки JWT |
| `ADMIN_SECRET` | `server/routes/admin.js`, `server/admin.js` | Ключ административных запросов |
| `DB_PATH` | `server/db.js` | Путь к SQLite, по умолчанию `server/emissium.db`; в Docker — `/app/data/emissium.db` |
| `STATIC_DIR` | `server/index.js` | Каталог собранного клиента; при заданном значении API также отдаёт сайт и админку |
| `VITE_API_URL` | `src/api/auth.js`, при сборке Vite | Адрес API клиента, по умолчанию `/api` |

Сервер читает переменные через `process.env`; автоматическая загрузка `.env` в коде не настроена. В PowerShell их можно задать через `$env:ИМЯ = 'значение'` перед запуском процесса. Для API и админки следует задать одинаковый `ADMIN_SECRET`: текущие значения по умолчанию в `server/admin.js` и `server/routes/admin.js` различаются, поэтому ключ, напечатанный сервером админки без этой переменной, не совпадает с ключом проверки API.

Клиент обращается к `/api`, админка — к `/admin` на том же адресе, с которого открыты. Для разработки `vite.config.js` проксирует `/api` на `http://localhost:3001`; при смене локального порта API нужно обновить цель прокси. В Docker сайт, админка и API работают через один порт `8080`.

## Особенности текущего проекта

- `requirements.txt` — справочный перечень npm-пакетов. Для установки используются npm-манифесты и lock-файлы; Python-зависимостей в проекте нет.
- `better-sqlite3` объявлен и в корневом, и в серверном `package.json`, хотя импортируется только сервером.
- SQLite не требует отдельного сервиса: файл БД и таблица создаются серверным кодом при первом запуске.
- В CSS подготовлены светлая и тёмная темы, но компонент `ThemeToggle` сейчас не подключён к страницам.
- Карусель ссылается на `/images/slide1.png`, `/images/slide2.png` и `/images/slide3.png`; в текущем проекте эти файлы отсутствуют, предусмотрено отображение заглушек.
- Автоматические тесты, линтер, TypeScript и CI в текущих файлах проекта не настроены.
